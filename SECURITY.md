# Security policy

## Supported versions

Security fixes are applied to the latest released minor version. Older versions should be upgraded before reporting an environment-specific problem.

## Reporting a vulnerability

Use the repository's private GitHub Security Advisory reporting flow. Do not open a public issue for suspected authentication bypasses, authorization failures, credential exposure, malicious-file processing, or data disclosure.

Include the affected version, deployment shape, reproduction steps using synthetic data, impact, and any suggested remediation. Never attach real credentials, session cookies, API tokens, SynBioHub tokens, raw confidential data, or database backups.

Maintainers should acknowledge a report within five working days, provide a status update within ten working days, and coordinate disclosure after a fix is available.

BOB has not been certified for regulated human data. Deployments remain responsible for institutional security review, host hardening, encryption, backups, and access policy.
